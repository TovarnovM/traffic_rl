Implement:

    @dataclass(frozen=True, slots=True)
    class SimulationParams:
        num_lanes: int
        road_length: int
        vmax_default: int = 5
        vmax_controlled: int = 6
        G: int = 15
        q: float = 0.99
        r: float = 0.99
        S: int = 2
        P1: float = 0.999
        P2: float = 0.99
        P3: float = 0.98
        P4: float = 0.01
        p_lane_change: float = 0.5

Context for defaults:
- These defaults correspond to the intended Revised S-NFS baseline.
- Ordinary vehicles use vmax_default=5.
- Future controlled/RL vehicles may use vmax_controlled=6.
- G, q, r, S, P1-P4 and p_lane_change are model parameters.
- This task only stores and validates them. It must not implement the model equations.

Validation requirements:
- Validate in __post_init__.
- Raise ValueError with a useful message if invalid.
- num_lanes must be int and > 0.
- road_length must be int and > 0.
- vmax_default must be int and >= 0.
- vmax_controlled must be int and >= 0.
- G must be int and >= 0.
- S must be int and >= 1.
- q must be in [0.0, 1.0].
- r must be in [0.0, 1.0].
- P1, P2, P3, P4 must be in [0.0, 1.0].
- p_lane_change must be in [0.0, 1.0].

Implementation note:
- Because the dataclass is frozen, use validation only, not mutation.
- Do not silently cast values. If num_lanes=4.0 is passed, reject it. Keep the schema strict.

Also add a small helper if useful:

        return max(params.vmax_default, params.vmax_controlled)

src/snfs_traffic/core/state.py
==============================
Implement:

    @dataclass(slots=True)
    class TrafficState:
        vehicle_id: np.ndarray
        lane: np.ndarray
        pos: np.ndarray
        vel: np.ndarray
        length: np.ndarray
        veh_type: np.ndarray
        behavior_id: np.ndarray
        alive: np.ndarray
        last_lane_delta: np.ndarray
        changed_lane: np.ndarray
        controlled: np.ndarray

Field meanings:
- vehicle_id: stable integer vehicle IDs, dtype int32, shape [N].
- lane: lane index for each vehicle, dtype int16, shape [N].
- pos: cell position along the road segment/ring, dtype int32, shape [N].
- vel: current discrete velocity in cells per step, dtype int16, shape [N].
- length: vehicle length in cells, dtype int16, shape [N].
- veh_type: integer vehicle type code, dtype int16, shape [N]. Meanings are not defined in this task.
- behavior_id: integer behavior/rule code, dtype int16, shape [N]. Meanings are not defined in this task.
- alive: whether the slot is active, dtype bool, shape [N].
- last_lane_delta: actual previous lane movement, dtype int8, shape [N], expected values {-1, 0, +1}.
- changed_lane: whether the vehicle actually changed lane on the previous step, dtype bool, shape [N].
- controlled: whether the vehicle is externally/RL controlled, dtype bool, shape [N].

Add:

    @property
    def n_vehicles(self) -> int:
        ...

Add:

    def copy(self) -> "TrafficState":
        ...

The copy must be a deep copy of all arrays. Mutating the copy must not mutate the original.

Add validation function:

        ...

Validation requirements:
1. Every field must be a NumPy ndarray.
2. Every field must be one-dimensional.
3. Every field must have the same shape.
4. Dtypes must be exact:
   - vehicle_id: np.int32
   - lane: np.int16
   - pos: np.int32
   - vel: np.int16
   - length: np.int16
   - veh_type: np.int16
   - behavior_id: np.int16
   - alive: np.bool_
   - last_lane_delta: np.int8
   - changed_lane: np.bool_

5. Arrays should be C-contiguous. Reject non-contiguous arrays with a useful error.
6. For alive vehicles only:
   - vehicle_id must be >= 0.
   - vehicle_id values must be unique among alive vehicles.
   - lane must satisfy 0 <= lane < params.num_lanes.
   - pos must satisfy 0 <= pos < params.road_length.
   - vel must satisfy 0 <= vel <= max(params.vmax_default, params.vmax_controlled).
   - length must be >= 1.
   - last_lane_delta must be one of -1, 0, +1.
   - changed_lane must be consistent with last_lane_delta:
       changed_lane == (last_lane_delta != 0)

Error message requirements:
- Raise ValueError.
- Include the relevant field name in the error message where practical.
- Keep validation simple and explicit.
