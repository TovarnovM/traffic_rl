# Kernel behavior requirements

The kernels should operate on arrays/scalars rather than `TrafficState`, `SimulationParams`, or `RingTopology`.

The kernels should assume already validated inputs. Do not duplicate the full public validation layer inside kernels.

The kernels must not mutate their input arrays.

Output requirements:

* `compute_longitudinal_velocities_kernel(...)` returns a new velocity array.
* Returned velocity dtype should match the input `vel.dtype`.
* Dead/inactive vehicles must keep their original velocity unchanged.
* `advance_positions_kernel(...)` returns a new position array.
* Returned position dtype should match the input `pos.dtype`.
* Dead/inactive vehicles must keep their original position unchanged.
* Alive positions must be advanced as periodic ring positions:

```python

```

# Important RNG rule

Preserve exact current RNG draw behavior.

Do not pre-generate random arrays.

Do not vectorize stochastic draws.

Do not change the number of `rng.random()` calls.

Do not change the order of `rng.random()` calls.

The longitudinal velocity kernel may accept `rng` and call `rng.random()` inside the same vehicle-index loop as the current reference implementation.

Although this is not Numba-ready yet, exact stochastic equivalence is more important in this task than premature Numba compatibility.

The public `step_longitudinal_reference(...)` must continue to validate that `rng` is an instance of `np.random.Generator`.

The internal kernel does not need to validate the rng type. This makes it easier to unit-test draw ordering with a tiny fake RNG object if useful.

# Existing longitudinal semantics to preserve exactly

For each vehicle index `i` in ascending order:

Skip if not alive.

Current semantics are:

```python
old_v = int(state.vel[i])
vmax_i = params.vmax_controlled if state.controlled[i] else params.vmax_default

if front_id[i] == -1:
    gap_i = params.road_length - 1
    leader_v = vmax_i
else:
    gap_i = front_gap[i]
    leader_v = state.vel[front_id[i]]

v = min(old_v + 1, vmax_i)

if front_id[i] != -1 and gap_i <= params.G:
    anticipated_leader_motion = max(leader_v - params.S, 0)
    anticipated_gap = gap_i + anticipated_leader_motion
    v = min(v, anticipated_gap)

if old_v == 0 and v > 0 and rng.random() < params.r:
    v = 0

brake_prob = params.P4
if front_id[i] != -1 and gap_i <= params.S:
    brake_prob = max(brake_prob, 1.0 - params.P2)
elif front_id[i] != -1 and gap_i <= params.G:
    brake_prob = max(brake_prob, 1.0 - params.P3)

if v > 0 and rng.random() < brake_prob:
    v -= 1

if front_id[i] != -1:
    v = min(v, gap_i)

v = max(0, min(v, vmax_i))
```

Then positions are updated only after all new velocities are computed.

This two-phase order must remain unchanged:

1. Compute all new velocities from the old state.
2. Apply positions using the new velocities.

Do not update position immediately inside the velocity loop.
