You are working in a new repository for a high-performance traffic simulation project.

Project context
===============
This repository will become a new implementation of a Revised S-NFS traffic simulator intended for future multi-agent reinforcement learning experiments.

S-NFS context, only for orientation:
- The future simulator will model multi-lane cellular-automaton traffic.
- Vehicles will later be represented as arrays, not as Python objects.
- The hot simulation loop will later be optimized with Numba/Cython.
- The project will later support RL agents, graph observations, RLlib adapters, and possibly complex road topology.
- None of that simulation logic should be implemented in this first task.

The repository currently contains:
- PLAN.md with the long-term implementation plan.
- .devcontainer/ with Docker/devcontainer setup.
- docker-compose.dev.yml.
- docker_stuff/.
- No Python package structure yet.
- No pyproject.toml yet.
- No tests yet.

Goal of this task
=================
Bootstrap the Python project structure cleanly.

This task must create the basic package layout, packaging metadata, README, and minimal smoke tests. Do not implement any S-NFS physics, lane changing, vehicle dynamics, RL environments, graph observations, or Numba kernels yet.

Important architectural constraints
===================================
1. The future core simulator must be independent from RL frameworks.
2. The future package name should be importable as:

   import snfs_traffic

3. Create subpackages for future layers, but leave them mostly empty for now.
4. Do not introduce Vehicle, RoadLane, TrafficModel, Agent, Env, or other object-heavy simulator classes in this task.
5. Do not copy or recreate any old object-oriented architecture.
6. Do not add RLlib, Ray, PyTorch, Gymnasium, matplotlib, pandas, or other heavy dependencies in this task.
7. Do not modify docker-compose.dev.yml unless absolutely necessary.
8. Do not refactor the existing devcontainer or docker files except for dependency alignment if strictly needed.
9. Keep the diff small, clean, and foundational.

===========================
Create a modern minimal pyproject.toml.

Use setuptools backend.

- Python version: >=3.11

  - numpy>=1.23

- Configure pytest so tests can import the package from src without requiring manual PYTHONPATH.

    [build-system]
    requires = ["setuptools>=68", "wheel"]
    build-backend = "setuptools.build_meta"

    [project]
    name = "snfs-traffic"
    version = "0.1.0"
    description = "High-performance Revised S-NFS traffic simulator for future multi-agent reinforcement learning experiments."
    readme = "README.md"
    requires-python = ">=3.11"
    dependencies = [
        "numpy>=1.23",
    ]

    [tool.setuptools.packages.find]
    where = ["src"]

    [tool.pytest.ini_options]
    testpaths = ["tests"]
    pythonpath = ["src"]

- keep it minimal.

- do not import numpy at top level unless needed.

In each subpackage __init__.py:
- keep it minimal.
- optionally add a one-line docstring describing the future purpose of the subpackage.
- do not add implementation code.

Subpackage intended purposes
============================
Use these meanings when writing docstrings:

- core: future high-performance S-NFS state transition engine.
- topology: future road topology abstractions such as ring roads, open boundaries, and road graphs.
- scenarios: future scenario initialization and traffic generation utilities.
- rules: future vehicle behavior rule identifiers and rule presets.
- observations: future full-state, local-grid, and graph observation builders.
- envs: future Gymnasium/RLlib/PettingZoo adapters.
- metrics: future traffic metrics and validation tools.
- io: future snapshots and serialization helpers.
