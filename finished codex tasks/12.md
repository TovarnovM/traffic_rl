# Current indexing semantics

Preserve these semantics exactly:

```text
- periodic RingTopology only;
- head-cell-only occupancy;
- occupancy[lane, pos] = vehicle_index for alive vehicle head cells;
- vehicle length is metadata only;
- no body-cell occupancy;
- no length-aware bumper-to-bumper gaps;
- gaps are head-cell empty-cell gaps;
- one alive vehicle = one occupied head cell;
- duplicate alive head cells are invalid;
- inactive vehicles are ignored by occupancy/neighbors;
- lane_order is sorted by increasing position inside each lane;
- lane_counts[lane] is the number of alive vehicles in that lane;
- lane_rank[vehicle_idx] is the rank inside its lane, or MISSING_INDEX for inactive/not-present vehicles;
- compute_neighbors returns front_id, back_id, front_gap, back_gap;
- for a lane with <= 1 alive vehicle, that vehicle has missing front/back neighbor and missing gaps;
- for a periodic lane with >= 2 vehicles, front/back wrap around the ring;
- front_gap/back_gap are computed as periodic forward distance minus 1;
- periodic_forward_distance(a, b) is `(b - a) % road_length`.
```

# Implementation details

## build_occupancy_numba

Input:

```text
lane: int lane array, shape (n_vehicles,)
pos: int position array, shape (n_vehicles,)
alive: bool array, shape (n_vehicles,)
num_lanes: scalar int
road_length: scalar int
```

Output:

```text
occupancy: int32 array, shape (num_lanes, road_length), C-contiguous
```

Semantics:

```text
- allocate int32 occupancy;
- initialize every cell to MISSING_INDEX;
- for vehicle index i:
  - if alive[i] is False, ignore it;
  - otherwise write occupancy[lane[i], pos[i]] = i;
- if two alive vehicles occupy the same head cell, raise ValueError;
- do not mark body cells;
- do not use vehicle_id;
- do not sort.
```

Implementation should use explicit loops instead of `np.full` if that is simpler and more robust under Numba:

```python
occupancy = np.empty((num_lanes, road_length), dtype=np.int32)
for lane_idx in range(num_lanes):
    for pos_idx in range(road_length):
        occupancy[lane_idx, pos_idx] = MISSING_INDEX
```

For duplicate detection in Numba, use a simple literal message:

```python
raise ValueError("duplicate occupied head cell")
```

Do not attempt dynamic f-string messages inside njit code.

## build_lane_order_numba

Input:

```text
occupancy: int32 array, shape (num_lanes, road_length)
n_vehicles: scalar int
```

Output:

```text
lane_order: int32 array, shape (num_lanes, road_length)
lane_counts: int32 array, shape (num_lanes,)
lane_rank: int32 array, shape (n_vehicles,)
```

Semantics:

```text
- initialize lane_order with MISSING_INDEX;
- initialize lane_rank with MISSING_INDEX;
- initialize lane_counts with 0;
- scan each lane by increasing position;
- every occupied head cell contributes its vehicle index to lane_order[lane, rank];
- lane_counts[lane] stores the number of occupied head cells in that lane;
- lane_rank[vehicle_idx] stores the rank of that vehicle in its lane;
- preserve exact ordering semantics of build_lane_order_kernel.
```

Avoid `np.unique`, Python sets, Python lists, dictionaries, or object-mode constructs.

## compute_neighbors_numba

Input:

```text
lane: int lane array, shape (n_vehicles,)
pos: int position array, shape (n_vehicles,)
alive: bool array, shape (n_vehicles,)
lane_order: int32 array, shape (num_lanes, road_length)
lane_counts: int32 array, shape (num_lanes,)
lane_rank: int32 array, shape (n_vehicles,)
road_length: scalar int
```

Output:

```text
front_id: int32 array, shape (n_vehicles,)
back_id: int32 array, shape (n_vehicles,)
front_gap: int32 array, shape (n_vehicles,)
back_gap: int32 array, shape (n_vehicles,)
```

Semantics:

```text
- initialize ids with MISSING_INDEX;
- initialize gaps with MISSING_GAP;
- inactive vehicles remain missing;
- lane with <= 1 alive vehicle gives missing neighbors/gaps;
- for count >= 2:
  - rank = lane_rank[i]
  - front_rank = (rank + 1) % count
  - back_rank = (rank - 1) % count
  - front_id/back_id come from lane_order;
  - front_gap = ((pos[front_id] - pos[i]) % road_length) - 1
  - back_gap = ((pos[i] - pos[back_id]) % road_length) - 1
```

For invalid but structurally possible inputs, preserve the same defensive checks that already exist in `compute_neighbors_kernel` if Task 11 included them inside the pure-array kernel. If Task 11 kept those checks only in the public wrapper, keep the Numba implementation minimal and focus on valid-input equivalence.

Do not move validation from public wrappers into Numba functions.

Do not weaken public wrapper validation.
