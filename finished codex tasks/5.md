==================
This repository is a clean new implementation of a Revised S-NFS traffic simulator intended for future multi-agent reinforcement learning experiments.

The long-term architecture is array-oriented:
- simulator state is stored in NumPy arrays;
- no Python Vehicle / RoadLane / TrafficModel object model in the hot loop;

- no gymnasium/ray/torch/rllib/pandas/scipy/matplotlib/networkx in core/scenarios/topology at this stage;

Important scope decision
========================
This task must implement HEAD-CELL indexing only.

Even if a vehicle has length > 1, including buses from VehicleMix, occupancy marks only:
    occupancy[lane, head_pos] = vehicle_index

Do not mark body cells.

Reason:
- the previous scenario initializer guarantees unique head cells only;
- full multi-cell occupancy and length-aware collision geometry are intentionally deferred;
- supporting body-cell occupancy now would create hidden complexity and conflicts with the current initializer contract.

Document this clearly in indexing.py and in README.

Gap semantics in this task:
- front_gap/back_gap are head-cell empty gaps.
- For two vehicles on the same lane, positions 2 and 5 on a ring:
      gap from 2 to 5 = forward_distance(2, 5) - 1 = 2
- Vehicle length is ignored in gap calculation for now.
- Length-aware bumper-to-bumper gaps are a future task.

Public function semantics
=========================

1. build_occupancy(state, params) -> occupancy
----------------------------------------------
Input:
- TrafficState
- SimulationParams

Behavior:
- First call validate_state(state, params).
- Create occupancy with shape:
      (params.num_lanes, params.road_length)
- dtype:
      np.int32
- Fill with -1.
- For every alive vehicle index i:
      lane = state.lane[i]
      pos = state.pos[i]
      occupancy[lane, pos] = i
- Store vehicle array index, not vehicle_id.
- Ignore inactive vehicles:
      state.alive[i] == False should not appear in occupancy.
- Detect duplicate alive head cells:
      if two alive vehicles have the same (lane, pos), raise ValueError.
- Return a C-contiguous array.

Important:
- Occupancy is head-cell occupancy only.
- Do not use state.length for occupancy.
- Do not mark bus body cells.

Validation:
- If duplicate head cells are found, raise ValueError with a useful message containing "duplicate" or "occupied".
- If state is invalid according to validate_state, let validate_state raise.

Implementation hint:
- Simple O(N) fill is fine:
      occupancy = np.full((num_lanes, road_length), -1, dtype=np.int32)
      for i in range(state.n_vehicles):
          if not state.alive[i]:
              continue
          ...
- Do not over-optimize.
- Do not use sorting here.

2. build_lane_order(occupancy, *, n_vehicles) -> lane_order, lane_counts, lane_rank
----------------------------------------------------------------------------------
Input:
- occupancy from build_occupancy
- n_vehicles = state.n_vehicles

Behavior:
- Validate occupancy:
    - must be np.ndarray;
    - must be 2D;
    - must have dtype np.int32;
    - must be C-contiguous;
    - values must be either -1 or in [0, n_vehicles);
    - no vehicle index may appear more than once.
- Validate n_vehicles:
    - Python int;
    - bool rejected;
    - n_vehicles >= 0.

Return:
    lane_order:  np.ndarray[int32], shape (num_lanes, road_length)
    lane_counts: np.ndarray[int32], shape (num_lanes,)
    lane_rank:   np.ndarray[int32], shape (n_vehicles,)

Semantics:
- lane_order[lane, rank] stores vehicle index at that rank in the lane.
- Vehicles are ordered by increasing position because occupancy is scanned from pos=0 to pos=road_length-1.
- Unused slots in lane_order are -1.
- lane_counts[lane] is the number of occupied head cells in that lane.
- lane_rank[i] is the rank of vehicle i within its lane.
- Missing/inactive vehicles have lane_rank[i] == -1.
- Return arrays must be C-contiguous and dtype np.int32.

Example:
    occupancy lane 0:
      pos 0 -> vehicle 5
      pos 3 -> vehicle 2
      pos 9 -> vehicle 7

    lane_order[0, :3] == [5, 2, 7]
    lane_counts[0] == 3
    lane_rank[5] == 0
    lane_rank[2] == 1
    lane_rank[7] == 2

Implementation hint:
- Scan occupancy by lane and then by position.
- This is intentionally O(num_lanes * road_length).
- For expected MVP sizes, e.g. 4 lanes * 1500 cells, this is cheap and more predictable than N log N sorting.

3. compute_neighbors(...) -> front_id, back_id, front_gap, back_gap
-------------------------------------------------------------------
Input:
- state
- lane_order
- lane_counts
- lane_rank
- topology

Behavior:
- Compute same-lane front/back neighbor for every alive vehicle.
- Use periodic ring semantics from RingTopology.
- Vehicle indices are state array indices, not vehicle_id values.

Return:
    front_id:  np.ndarray[int32], shape (N,)
    back_id:   np.ndarray[int32], shape (N,)
    front_gap: np.ndarray[int32], shape (N,)
    back_gap:  np.ndarray[int32], shape (N,)

Defaults:
- All arrays initialized with -1.
- Inactive vehicles remain -1 for ids and gaps.
- Vehicles on lanes with 0 or 1 alive vehicle have:
      front_id[i] = -1
      back_id[i] = -1
      front_gap[i] = -1
      back_gap[i] = -1

For lanes with at least 2 vehicles:
- front is next rank modulo lane_counts[lane].
- back is previous rank modulo lane_counts[lane].
- front_gap is:
      topology.forward_distance(state.pos[i], state.pos[front_idx]) - 1
- back_gap is:
      topology.forward_distance(state.pos[back_idx], state.pos[i]) - 1

Important:
- Gaps are head-cell empty gaps.
- Length is ignored.
- If positions are adjacent in the forward direction, gap is 0.
- With periodic wraparound, a vehicle at pos=9 and front at pos=0 on length=10 has front_gap=0.

Validation:
- topology must be periodic RingTopology-compatible.
- topology.num_lanes must match lane_order.shape[0].
- topology.length must match lane_order.shape[1].
- lane_counts must have shape (num_lanes,).
- lane_rank must have shape (state.n_vehicles,).
- lane_order must have dtype int32.
- lane_counts must have dtype int32.
- lane_rank must have dtype int32.
- lane_order/lane_counts/lane_rank should be C-contiguous.
- If a live vehicle has lane_rank == -1, raise ValueError.
- If lane_order and lane_rank are inconsistent, raise ValueError.

Keep validation explicit but not overengineered.

Do not mutate input arrays.
