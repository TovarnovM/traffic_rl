Scientific / model source
=========================
Implement the lane-changing rule described in the attached paper:

    2025_BKT_Interceptors_Chaos.pdf

The paper states that lane-changing follows Kukida et al. and is considered when both conditions are satisfied.

Incentive criterion, Eq. (8):

    g_i^(n,f) + v_{i+1}^(n) > v_i >= g_i^(p,f) + v_{i+1}^(p)

Safety criterion, Eq. (9):

    v_i > v_{i-1}^(n) - g_i^(n,b)

Where:
- v_i is the speed of the vehicle considering the maneuver;
- g_i^(n,f) is the forward gap in the target/new lane;
- g_i^(n,b) is the backward gap in the target/new lane;
- v_{i+1}^(n) is the speed of the vehicle ahead in the target/new lane;
- v_{i-1}^(n) is the speed of the vehicle behind in the target/new lane;
- g_i^(p,f) and v_{i+1}^(p) are the forward gap and leading vehicle speed in the current/present lane.

If both criteria are satisfied, the lane change is attempted with probability P_CL = 0.5.

The paper uses:
- periodic closed-loop road;
- 3 lanes and road length 500 in experiments;
- vmax = 5 for ordinary vehicles;
- vmax = 6 for interceptor / controlled vehicles;
- P_CL = 0.5.

Repository-specific interpretation

- state.pos is the vehicle head cell;
- occupancy marks head cells only;
- vehicle length is metadata only;
- gaps are head-cell empty gaps;
- body cells are ignored;
- no length-aware bumper-to-bumper gaps.

Keep this unchanged.

Lane changes in this task are lateral only:
- lane may change by -1 or +1;
- pos does not change;
- vel does not change;
- no longitudinal movement is performed;
- no lateral wrapping: lane 0 cannot move to lane -1, lane num_lanes - 1 cannot move to lane num_lanes.

Use old state / old indexing only:
- all lane-change decisions are computed from the state at the beginning of the phase;
- do not let earlier accepted lane changes affect later vehicle decisions in the same phase;
- commit accepted lane changes simultaneously.

Lane-change candidate logic
===========================
For each alive vehicle i, consider only adjacent target lanes:

    target_lane = state.lane[i] - 1
    target_lane = state.lane[i] + 1

Skip target lanes outside [0, params.num_lanes).

Define lane_delta convention:
- -1 means lane index decreased;
- +1 means lane index increased.

Do not assume that -1 means physically left or right beyond this integer convention.

For each candidate target lane:
1. Target head cell must be empty in the old occupancy:
       occupancy[target_lane, state.pos[i]] == MISSING_INDEX
   If not empty, the candidate is invalid.

2. Compute present-lane forward gap and present-lane front velocity:
   - use existing same-lane neighbor indexing for current lane:
       front_id, back_id, front_gap, back_gap = compute_neighbors(...)
   - if front_id[i] == MISSING_INDEX:
       g_pf = params.road_length - 1
       v_p_front = vehicle_vmax(i)
     else:
       g_pf = int(front_gap[i])
       v_p_front = int(state.vel[front_id[i]])

3. Compute target-lane forward gap, target-lane front velocity, target-lane backward gap, target-lane back velocity at the current head position of vehicle i, using the OLD target lane occupancy/order.

   Required semantics:
   - vehicle i is not inserted into the target lane when searching;
   - use topology.forward_distance(...) for periodic distances;
   - gaps are head-cell empty gaps:
         gap_forward = forward_distance(candidate_pos, front_pos) - 1
         gap_backward = forward_distance(back_pos, candidate_pos) - 1
   - because target head cell occupancy is checked first, computed gaps should be >= 0;
   - if target lane has no alive vehicles:
         no target front and no target back;
         g_nf = params.road_length - 1
         v_n_front = vehicle_vmax(i)
         safety criterion is automatically true
   - if target lane has vehicles:
         find the first vehicle ahead and first vehicle behind on the target lane around candidate_pos;
         for a target lane with one vehicle, that vehicle may be both front and back on the ring.

4. Incentive criterion:
       g_nf + v_n_front > v_i >= g_pf + v_p_front

5. Safety criterion:
       if target lane has no back vehicle:
           safety = True
       else:
           safety = v_i > v_n_back - g_nb

6. Candidate is eligible only if both incentive and safety are true.

vehicle_vmax(i):
- params.vmax_controlled if state.controlled[i] else params.vmax_default

Important:
- Use current velocity state.vel[i] for v_i.
- Do not modify velocity here.
- This task does not implement controlled RL actions. Controlled vehicles use the same rule, only with vmax_controlled for missing-front free-road substitution if needed.
- Do not use vehicle length in gaps.

Choosing a lane when both adjacent lanes are eligible
=====================================================
If no adjacent lane is eligible:
- no lane-change attempt.

If one adjacent lane is eligible:
- that is the proposed target lane.

If both adjacent lanes are eligible:
- choose exactly one proposed target lane using stochastic tie-breaking:
      idx = rng.integers(0, len(eligible_targets))
      proposed_target = eligible_targets[idx]
- This must be deterministic for the same rng seed.
- Do not prefer lower/higher lane deterministically.

Lane-change attempt probability
===============================
After a proposed target lane has been selected, apply stochastic attempt probability:

    if rng.random() < params.p_lane_change:
        proposal is active
    else:
        no proposal

SimulationParams.p_lane_change must default to 0.5, matching P_CL = 0.5 from the paper.

Tests may set:
- p_lane_change=1.0 to force attempts;
- p_lane_change=0.0 to disable attempts.

Conflict resolution
===================
Multiple vehicles can simultaneously propose the same target head cell:

    key = (target_lane, pos)

Resolve conflicts after all proposals have been computed from the old state.

For each target-cell key:
- if exactly one vehicle proposes it, accept that proposal;
- if multiple vehicles propose it, choose exactly one winner uniformly at random:
      winner = candidates[rng.integers(0, len(candidates))]
  and reject all other proposals.

This is required stochastic tie-breaking.

Conflict resolution must be deterministic for the same rng seed.

No accepted result may contain duplicate alive head cells.

Conservative no-swap rule
=========================
Do not allow a vehicle to move into a target head cell that was occupied in the old state, even if that occupant also wants to change lanes away during the same phase.

Rationale:
- current occupancy is head-cell-only;
- this keeps the reference implementation simple and safe;
- swap semantics can be added later only if explicitly needed.
